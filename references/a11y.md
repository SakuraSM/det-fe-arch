# A11y 约束

本文件定义 DFA 的无障碍访问规则。涉及 UI、表单、弹窗、自定义控件、键盘交互或颜色状态时必须读取。

## 规则速查表

| 检查维度 | 强制约束 | WCAG 依据 |
|---|---|---|
| 色彩对比度 | 普通文本背景比 >= 4.5:1，大文本 >= 3:1 | 1.4.3 |
| 颜色传达信息 | 禁止颜色作为唯一手段，必须有文字、图标或 aria 描述 | 1.4.1 |
| 按钮语义 | 禁止 `div`/`span` + 点击事件代替 `button` | 4.1.2 |
| 焦点样式 | 禁止无替代地设置 `outline: none` | 2.4.7 |
| 弹窗焦点 | 必须实现 Focus Trap、初始焦点、关闭后焦点恢复 | 2.1.1 |
| 表单标签 | `label for` 与 `input id` 强制绑定，或使用 `aria-labelledby` | 1.3.1 |
| 媒体控制 | 禁止自动播放；音视频必须有暂停/静音控制 | 1.4.2 |
| 键盘操作 | 所有交互必须可通过键盘完成 | 2.1.1 |
| 页面结构 | 使用语义化 landmarks：header、nav、main、footer | 1.3.1 |

## 语义化 HTML

优先使用原生元素：

- 操作：`button`
- 链接跳转：`a`
- 页面主体：`main`
- 导航：`nav`
- 表格数据：`table`
- 列表：`ul`/`ol`

只有在原生元素无法表达自定义组件语义时，才使用 ARIA。

## ARIA 使用边界

ARIA 只能补充语义，不能修复错误语义。

```tsx
// 不推荐
<div role="button" tabIndex={0}>提交</div>

// 推荐
<button type="button">提交</button>
```

自定义控件必须同时实现：

- 正确的 `role`
- 可聚焦的 `tabIndex`
- `Enter` 和 `Space` 键行为
- 状态属性，例如 `aria-expanded`、`aria-selected`
- 可感知名称，例如 `aria-label` 或可见文本

## 键盘导航

- Tab 顺序必须符合视觉和操作顺序。
- Escape 应关闭弹窗、菜单、浮层。
- 箭头键用于菜单、列表框、标签页等复合控件内部导航。
- 禁止使用正数 `tabIndex` 改写自然焦点流。

## Focus Trap 模板

弹窗打开后必须把焦点移入弹窗，Tab 不应逃出弹窗，关闭后恢复到触发元素。

```ts
const FOCUSABLE_SELECTOR = [
  'a[href]',
  'button:not([disabled])',
  'textarea:not([disabled])',
  'input:not([disabled])',
  'select:not([disabled])',
  '[tabindex]:not([tabindex="-1"])',
].join(',')
```

实现要求：

1. 保存打开前的 `document.activeElement`。
2. 打开后聚焦标题、关闭按钮或第一个可交互控件。
3. 监听 Tab/Shift+Tab，把焦点循环限制在弹窗内。
4. 监听 Escape 关闭弹窗。
5. 卸载时移除事件监听并恢复焦点。

## 表单规范

每个输入控件必须有标签：

```tsx
<label htmlFor="email">邮箱</label>
<input id="email" name="email" type="email" aria-describedby="email-error" />
<p id="email-error" role="alert">请输入有效邮箱地址。</p>
```

错误状态必须同时具备：

- 可见错误文本。
- `aria-invalid="true"`。
- `aria-describedby` 指向错误说明。
- 不只依赖红色边框。

## Skip Link 模板

页面级布局应提供跳转到主内容的链接。

```tsx
<a className="skip-link" href="#main-content">
  跳到主要内容
</a>
<main id="main-content" tabIndex={-1}>
  ...
</main>
```

```css
.skip-link {
  position: absolute;
  transform: translateY(-120%);
}

.skip-link:focus {
  transform: translateY(0);
}
```

## 可豁免场景

若业务要求与 A11y 规则冲突，必须说明风险并提供替代方案。例如品牌色对比度不足时，应提供高对比主题、描边、背景块或字号加粗方案，而不是直接忽略。
